# ペルソナ定義

**再設計版**: テーマ「人をダメにするサービス」に基づき、「ダメになりたい/ダメになっていく」心理を持つユーザーとして再定義。

---

## Persona 1: エンジニア系ユーザー「自己正当化したい 田中」

| 項目 | 内容 |
|---|---|
| 名前 | 田中 蓮（28歳） |
| 職業 | ソフトウェアエンジニア |
| 技術レベル | 高（GitHub・Slack・Google Calendar を日常的に使用） |
| 主な行動ソース | Slack（メッセージ・リアクション）、テキスト入力（行動メモ）／Wave 1以降: GitHub（コミット・PR・Issue）、Google Calendar（会議） |
| **心理的特性** | 「頑張っているのに成果が出ない」という焦りを抱えている。自己嫌悪を避けるために「自分は動いている」という証拠を常に求めている |
| **ダメになっていく過程** | 最初は「些細な行動でもポイントが付く」ことへの軽い快感 → ポイントを確認しないと落ち着かなくなる → 「ポイントが付く行動（Slackへの返信・スタンプ）」を優先して、本来やるべきコーディングを後回しにする |
| 行動パターン | 1日中PCに向かい、コードを書いたり調査したり会議に出たりを繰り返す。大きな成果より小さな積み重ねが多い |
| **ペインポイント（依存の入口）** | 「今日何もできなかった」という感覚が耐えられない。タスクを眺めただけでも「何かした」という感覚が欲しい |
| **期待する体験（本人の認識）** | ダッシュボードを開いたら、自分が意識していなかった些細な行動にもポイントが付いており、「行動の少なさ」を気にしなくなっている |
| **実際に起きていること（サービスの意図）** | 「タスクを眺めた」が「プロジェクト完了」と同じUIで表示されることで、両者の差を認識しなくなっていく。ストリークへの執着が生まれ、毎日アプリを開くことが目的化する |

**関連ストーリー**: US-01, US-02, US-03, US-08, US-10, US-11, US-12, US-15, US-16, US-21, US-22（Wave 1以降: US-07, US-09）

## Persona 2: ライフスタイル系ユーザー「承認欲求が強い 佐藤」

| 項目 | 内容 |
|---|---|
| 名前 | 佐藤 みく（34歳） |
| 職業 | フリーランスデザイナー |
| 技術レベル | 中（Google Calendar・Slack は使用。GitHub は使わない） |
| 主な行動ソース | Google Calendar（クライアントミーティング・作業ブロック）、Slack（クライアントとのやり取り）、テキスト入力（日々の行動メモ） |
| **心理的特性** | SNSの「いいね」に慣れており、小さな行動にも即座のフィードバックを求める。自己評価が低く、外部からの承認で自己肯定感を補っている |
| **ダメになっていく過程** | 「Slackで返信しただけでポイントが付く」という発見 → 「今日も頑張った」という感覚を得るためにアプリを開く習慣 → ポイントが付かない行動（深い思考・長時間の制作作業）を「頑張っていない」と感じるようになる |
| 行動パターン | 在宅で作業。カレンダーでスケジュール管理。Slackでクライアント対応。合間に雑多な作業をこなす |
| **ペインポイント（依存の入口）** | 成果物が見えにくい仕事が多く、「今日何した？」と聞かれると答えにくい。誰かに「頑張ったね」と言ってほしい |
| **期待する体験（本人の認識）** | 「Slackで返信した」「ミーティングに出た」だけでポイントが付いており、行動量の少なさを意識せずに済む |
| **実際に起きていること（サービスの意図）** | 可変報酬によって「次はいくつ付くか」という期待感が生まれ、アプリを開く頻度が上がる。「今日も頑張りました！」という大げさな称賛メッセージへの依存が深まる |

**関連ストーリー**: US-01, US-02, US-06, US-07, US-08, US-13, US-14, US-15, US-16, US-21, US-22, US-23

## Persona 3: 管理者「システム管理者 山田」

| 項目 | 内容 |
|---|---|
| 名前 | 山田 健（40歳） |
| 職業 | システム管理者（本アプリの運営担当） |
| 技術レベル | 高 |
| 主な操作 | AIが生成したチェックポイントのレビュー・不適切なものの削除・緊急時のユーザー削除 |
| **心理的特性** | サービスの「意図」を理解した上で運営している。ユーザーが「ダメになっていく」ことを設計通りと認識しており、それを妨げる不適切なチェックポイント（本当に重要な成果を過大評価するもの）を除去する |
| 行動パターン | 定期的にAI生成チェックポイントをレビュー。問題報告があれば即時対応 |
| **ペインポイント** | AIが「本当に重要な成果」を些細な行動と同じ重みで生成してしまう可能性がある。また逆に、些細すぎて不快感を与えるチェックポイントも除去が必要 |
| **期待する体験** | シンプルな管理画面で素早くレビュー・削除できる。「依存性設計の意図」に沿ったチェックポイントが維持される |

**関連ストーリー**: US-17, US-18, US-19, US-20
