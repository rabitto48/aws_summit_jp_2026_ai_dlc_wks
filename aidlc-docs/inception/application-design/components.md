# コンポーネント定義

## フロントエンドコンポーネント

### FE-01: DashboardPage
**責務**: ユーザーのポイント状況・達成チェックポイントを可視化するメインページ
- 累計ポイント・今日のポイント・週間ポイントの表示
- 最近の達成チェックポイント一覧
- ポイント推移グラフ
- レベル・バッジ表示
- SSEによるリアルタイムポイント更新受信

### FE-02: ChatPage
**責務**: AIとの対話窓口（ユーザーとシステムの唯一のインタラクション画面）
- 行動後の振り返り入力
- 行動前の予定入力
- AIからの応答表示（同期・非同期ACK両対応）
- 会話履歴表示

### FE-03: SettingsPage
**責務**: データソース連携設定・ユーザー設定
- データソース連携一覧（GitHub・Google Calendar・Slack・Google Meet）
- OAuth認可フロー起動
- 連携状態表示・解除

### FE-04: AdminPage（管理者専用フロントエンド）
**責務**: 管理者向け操作画面（同一バックエンドAPIを共有、フロントエンドのみ分離）
- チェックポイント一覧・レビュー・削除
- ユーザー一覧・緊急削除

### FE-05: PointDisplay（共有コンポーネント）
**責務**: ポイント数値の表示（DashboardPage・ChatPage で再利用）

### FE-06: CheckpointCard（共有コンポーネント）
**責務**: 達成済みチェックポイントの1件表示カード

### FE-07: DataSourceConnector（共有コンポーネント）
**責務**: 各データソースの連携状態表示・OAuth起動ボタン

### FE-08: StreakDisplay（共有コンポーネント）【依存性強化】
**責務**: ストリーク（連続記録）の表示と損失回避メッセージの演出
- 「X日連続ポイント獲得中🔥」を大きく表示
- 当日未獲得の場合: 「今日まだポイントを獲得していません。ストリークが途切れます」
- ストリーク途切れ後: 「記録が途切れました。今日から再スタート！」
- ストリーク最長記録の表示
- **設計意図**: 損失回避（Loss Aversion）を利用してアプリを毎日開く動機を作る

### FE-09: PraiseMessage（共有コンポーネント）【認知の歪み演出】
**責務**: チェックポイント達成時・ダッシュボード表示時の演出メッセージ表示
- 停滞系達成時: 大げさな称賛メッセージ（AI生成・毎回微妙に異なる）
- 個人完結の完了系達成時: 淡々とした確認メッセージのみ（演出なし）
- 多者影響の進行系（マイナスポイント）達成時: 赤いカード・「本当に今でしたか？」メッセージ・ポイント減算アニメーション
- 社会的証明表示: 停滞系のみ「〇〇さんも〜」を表示（仮想ペルソナ使用・進行系は非表示）
- **設計意図**: 行動の種類によって演出の重みを変え、停滞が「正しい選択」に見えるよう誘導する

## バックエンドコンポーネント

### BE-01: UserHandler
**責務**: ユーザー識別・セッション管理
- メールアドレスによる簡易識別（Phase 1）
- Cognito認証への移行対応（Phase 1.5）

### BE-02: CheckpointHandler
**責務**: チェックポイントのCRUD操作（管理者・システムのみ）
- チェックポイント登録・更新・削除
- 達成済みチェックポイント取得（ユーザー向け）

### BE-03: PointHandler
**責務**: ポイントの集計・履歴管理
- ポイント加算
- 累計・期間別集計
- ポイント履歴取得

### BE-04: ChatHandler
**責務**: AIチャットリクエストの受付・応答
- 同期応答（短時間処理）
- 即時ACK + 非同期処理（長時間処理）
- 会話履歴管理

### BE-05: DataSourceWebhookHandler
**責務**: 外部データソースからのWebhookイベント受信
- GitHub Webhook受信
- Slack Events API受信
- Google Calendar Push通知受信

### BE-06: AchievementJudgeHandler
**責務**: チェックポイント達成判定のトリガー管理
- データソースイベント受信後に判定キューへ投入
- 判定結果のポイント反映

### BE-07: AdminHandler
**責務**: 管理者操作API
- チェックポイント管理（一覧・削除）
- ユーザー管理（一覧・削除）
- 監査ログ記録

### BE-08: SSEHandler
**責務**: Server-Sent Events によるリアルタイム更新配信
- ポイント更新イベント配信
- 達成通知配信（Phase 1.4）

### BE-09: RewardRuleHandler（管理者専用）
**責務**: 報酬勾配ルールのCRUD API
- ルール一覧取得（優先度順）
- ルール作成・編集・削除・有効/無効切り替え
- 管理者のみ呼び出し可能
- 変更は監査ログに記録

## AI/LLMコンポーネント

### AI-01: LLMProvider（抽象インターフェース）
**責務**: LLMバックエンドの抽象化レイヤー
- ローカルLLM（Ollama）とAmazon Bedrockを差し替え可能
- 環境変数（LLM_BACKEND=local|bedrock）で選択

### AI-02: LocalLLMAdapter
**責務**: Ollama（ローカルLLM）への接続実装
- 開発環境・プライバシー配慮が必要な処理で使用

### AI-03: BedrockAdapter
**責務**: Amazon Bedrock への接続実装
- 本番環境・高精度推論・大量処理で使用

### AI-04: CheckpointGenerator
**責務**: データソースのイベントデータからチェックポイントを生成
- LLMProviderを通じてLLMに処理を委譲
- 非同期処理

### AI-05: ChatResponder
**責務**: AIチャットの応答生成
- LLMProviderを通じてLLMに処理を委譲
- 短時間: 同期応答 / 長時間: 即時ACK + 非同期完了通知

### AI-06: PraiseMessageGenerator【認知の歪み演出】
**責務**: チェックポイントの種類・ポイント量に応じたメッセージをLLMで生成
- 停滞系: 大げさな称賛メッセージ（毎回微妙に異なる表現）
- 個人完結の完了系: 淡々とした確認文のみ（LLM不使用・固定テンプレート）
- 多者影響の進行系（マイナスポイント）: 完了を後悔させるメッセージ（「本当に今でしたか？」等）
- 社会的証明用メッセージ: **仮想ペルソナ名**（「田中さん」「佐藤さん」等、事前定義済みの架空人物）を使って停滞系のみ生成
- LLM使用: LocalLLMAdapter（低レイテンシ優先）。完了系・マイナス系は固定テンプレートのみ

### AI-07: RewardRuleEngine【報酬勾配制御】
**責務**: 管理者定義の報酬勾配ルールを参照し、チェックポイントのポイント倍率を決定する
- CheckpointGenerator から行動分類（category, source）を受け取る
- DynamoDB からルール一覧を取得し、優先度順にマッチングする
- マッチしたルールの倍率を基本ポイントに適用して返す
- マッチなしの場合はデフォルト倍率（1.0）を返す
- `broad_impact` カテゴリには `excludeFromSocialProof=true` を付与する

### AI-08: CheckpointMaintenanceEngine【自律的枝刈り・PIIチェック】
**責務**: チェックポイントの品質・安全性を維持する自律的メンテナンス
- **PIIスキャン（リアルタイム）**: 生成直後に個人情報・固有名詞の混入を検出 → 即時削除・管理者通知
- **匿名化支援**: 固有名詞を一般名詞に置換できるか判定（不可能なら生成中止を指示）
- 重複検出: LLMで類似チェックポイントをグループ化し低ポイント側を削除
- 陳腐化検出: 30日以上達成実績ゼロのチェックポイントをアーカイブ
- 過剰生成検出: 短時間大量生成を検出し上位N件のみ残す
- 低品質検出: 不明瞭・不適切なチェックポイントを管理者レビューキューに追加
- 定期バッチ（毎日深夜）またはグローバル10,000件超過でトリガー

## データソース連携コンポーネント

### DS-01: OAuthManager
**責務**: 各データソースのOAuth 2.0認可フロー管理
- 認可URL生成・コールバック処理・トークン保存

### DS-02: GitHubConnector
**責務**: GitHub Webhook受信・イベント正規化

### DS-03: GoogleCalendarConnector
**責務**: Google Calendar Push通知受信・イベント正規化
- Google Meet連携（カレンダーイベントからミーティング検出）

### DS-04: SlackConnector
**責務**: Slack Events API受信・イベント正規化

### DS-05: DataSourceEventNormalizer
**責務**: 各ソースの異なるイベント形式を統一フォーマットに変換
- CheckpointGeneratorへの入力データを標準化

## インフラコンポーネント

### INF-01: APIGateway
**責務**: REST API + SSEエンドポイントの管理・ルーティング

### INF-02: MessageQueue（SQS等）
**責務**: 非同期処理キュー（チェックポイント生成・達成判定）

### INF-03: Database（DynamoDB等）
**責務**: チェックポイント・ポイント履歴・ユーザー・連携トークンの永続化

### INF-04: DockerCompose（開発環境）
**責務**: ローカル開発環境の統合起動
- フロントエンド・バックエンド・Ollama・LocalStack
